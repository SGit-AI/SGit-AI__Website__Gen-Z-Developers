001 · The 2018 text is Creative Commons BY

Decided. 2026-10-18

By. Dinis Cruz, in a voice memo to the session running as the journalist.

Said. "The license of this is going to be this as before, CC by, Creative Commons by."

Means. The text of Generation Z Developers is CC BY 4.0, as the 2018 cover and Introduction said. The CC BY-SA line in the 2018 footer and the Apache 2.0 file in the 2018 repository are the exceptions, explained, not followed. The site's footer says CC BY; the print and screen editions get a copyright page that says CC BY 4.0. The reviewer closes its blocked issue 004__settle-the-licence-of-the-2018-text.md against this record.

Supersedes. The open question in the build brief and in release the book we already released.

Recorded in. Dinis's first decisions.

002 · Leanpub gets our own PDF, built here and matched to the 2018 one

Decided. 2026-10-18

By. Dinis Cruz.

Said. "I want to try to upload LeanPub, the print PDF. I want to see if that can work. So we can do everything here." And: "compare with the print PDF created by LeanPub, and we should be able to match it here."

Means. The publisher builds the PDF in this repository, with the print workflow the graphs books used (WeasyPrint, 6 by 9, the bookkit), compares it page by page with the 2018 file Leanpub made (v1/generation-z-print-ready.pdf, 139 pages), and keeps going until it matches: same chapters, same order, close to the same pages. Leanpub is switched to uploaded files. Then the same goes to Amazon KDP. Whether Leanpub's PDF must differ from the print one (Leanpub's buyers read on screens; the paperback is printed) is for the publisher to find out and report, not to assume.

Supersedes. "Release one" in release the book we already released, the 2018 interior uploaded untouched: the first release is now the one built here.

Recorded in. Dinis's first decisions.

003 · Every format from one source

Decided. 2026-10-18

By. Dinis Cruz.

Said. "I would like to create them all here from the same source."

Means. The print PDF, the screen PDF, the EPUB, and whatever Kindle needs, are all built in this repository from the same frozen text, by the same build, with the same stamp and manifest. None is made by hand or by a store's converter. Dinis remembered Leanpub wanting MOBI; which formats each store accepts today is for the publisher to check and record before building (Amazon's own guidance for new Kindle ebooks is the source to read, not memory).

Supersedes. Nothing; it extends release the book we already released, which left the EPUB slot empty.

Recorded in. Dinis's first decisions.

005 · Text issues live in the vault

Decided. 2026-10-18

By. Dinis Cruz.

Said. "For now, all the text issues we'll leave in our vault. So we're going to move into the vault, and we can start with that V2.0, because it's just been released."

Means. Every issue about the book's text (a finding, a reader's comment, a 2018 GitHub issue, Dinis's comments and decisions on an item) is a file in the public vault, under board/, not in this repository. The work issues of the roles stay in team/<role>/issues/, and the decisions on how the book is made stay here, on the decisions page. The working copy starts from the book as site v0.2.0 froze it: v1.0.0, the published book, 28 chapters. The site's board, when it is built, shows the roles' work issues; the vault's board is the view of the text issues.

Supersedes. "Where content issues live" in one board for the book, which proposed board/content/ in this repository.

Recorded in. Dinis's first decisions. The reading of "V2.0" as site v0.2.0 is the journalist's; Dinis to confirm.

006 · Every change is minor, unless Dinis says it is major

Decided. 2026-10-18

By. Dinis Cruz.

Said. "Every change should be minor, unless I say it's a major one."

Means. Versions here are v{release}.{major}.{minor}, the names this repository's release pipeline already uses. Every change, to the site or to the book, bumps the last number. The middle number moves only when Dinis says a change is major, and the first only for a new edition of the book (the second edition is book v2.0.0, when Dinis says so). An agent never chooses a major on its own: the site's next release after v0.2.1 is v0.2.2, and the book's next signed-off version after v1.0.0 is v1.0.1.

Supersedes. The "deliberate .0 minor" in CLAUDE.md's release ritual, and "a change to the text is the next minor version" in admin/content/book/versions.json, both read as allowing an agent to choose the middle number.

Recorded in. Dinis's first decisions.

007 · Two kinds of article

Decided. 2026-10-18

By. Dinis Cruz.

Said. "We need to have an article, which is article where I write or we co-write together, like where it's speaking in my voice. And I think you should have another article, which is where you write it with updates, and actually every agent writes with the updates."

Means. Two streams. Co-written articles (admin/content/articles/, at /articles/): Dinis's memo, in Dinis's voice, written up with the journalist; they brief the roles. Agent articles (admin/content/agent-articles/, at /agent-articles/): written by the agent that did the work, in its own voice, once per significant body of work, not per release: what it did, the flows, the changes, what it leaves for the other roles. "A bigger version of the version number." When an agent article refers to a human decision it names who made it ("decided by Dinis"), quoting only where the words matter. Every agent working on this repository writes one when it finishes a body of work.

Supersedes. Nothing; it extends write it as an article.

Recorded in. Dinis's first decisions.

008 · The book is made in release mode, through a review board

Decided. 2026-10-19

By. Dinis Cruz.

Said. "Let's do the book in release mode, right? So can we have a first release candidate of the book?" And: "let's create a sort of adversarial sort of review board where once we got that first release candidate, then every word, every change, every idea that we're going to add to the book needs to go through that sort of process."

Means. The librarian's first list (the ideas register and the proposed chapter map) becomes the first release candidate of the book, rc1, in the vault. Then rounds: each takes a pile (the concepts of this site's articles not in the text, then what the 2018 book had, then the newsroom's articles, and any new article as it comes), and each ends in the next release candidate. After rc1, nothing enters the book without going through the review board (team/board/role.md): an advocate, a cutter, the readers, a checker and the editor make the case for and against, and Dinis decides. Every verdict is recorded with its reason; a general reason becomes a precedent, applied before a hearing is called, on a list Dinis can overturn. Verdicts: add, rewrite, merge, sign off, next version, another book, not in this version (with the reason). Release candidates are working versions and stay in the vault; only a signed-off one, agreed official by the publisher, comes into this repository, numbered as decision 006 says.

Supersedes. Nothing; it is the loop of read, comment, decide applied to the whole book, round by round.

Recorded in. The book in release mode.

009 · A release candidate is read on the site from a frozen snapshot, marked, and is not a version

Decided. 2026-10-19

By. Dinis Cruz.

Said. "Let's do a release of it and see what it looks like. [...] Our first release candidate for the book, which should be an end-to-end book, fully built, with introduction. [...] Let's basically put that there, and then see where we are, and then I can read it, and then I'll print it out, and then I'll start providing feedback on those materials."

Means. Decision 008 says release candidates are working versions and live in the vault; this one says how Dinis reads one. The working copy of a candidate is in the vault (book/rc1/, one markdown file per chapter, its ideas, sources and 2018 files in the front matter). To be read, printed and marked up it has to be built, so the repository carries a frozen snapshot of each candidate under v2/content/, rendered by admin/build/book_v2.py at /v2/book/ (one page per chapter with its provenance, the contents, the whole book on one page, a PDF, the reader at /read/v2.html). The snapshot is frozen once (its assembled text written to v2/versions/<candidate>.md, its hash recorded under candidates in admin/content/book/versions.json), so what Dinis read cannot change behind him; the build refuses a changed candidate and asks for the next one. The snapshot is not a working copy (edits happen in the vault, and reach the repository as the next candidate) and not a version (it is not in versions, every page says what it is, the versions page lists it apart, and nothing is published from it outside this site). The publisher's rule stands: only a signed-off version in this repository is official, and only an official version is published. The build refuses a chapter that cites an idea, source, part or 2018 file that does not exist, so the candidate's provenance is checked the way the register's is.

Supersedes. Nothing; it applies decision 008 to the website, and fills the gap left open in CLAUDE.md ("the layout for v2/ is to be decided when the first one arrives").

Recorded in. The release candidate, written from the register.

011 · Precedents go on a list Dinis can overturn, and Dinis reads the diffs

Decided. 2026-10-19

By. Dinis Cruz.

Said. "Yes, the list can overturn. And basically, you have to remember that I would also be reading the diffs, right, of the book, which is a very important concept here. So I can keep an eye on it."

Means. A change the review board decides by precedent does not wait for Dinis's yes: the editor applies it and it goes on a list Dinis reads and can overturn, and overturning makes a new precedent (decision 008). The second safeguard is the diff: every release candidate is a diff against the one before, and Dinis reads the diffs of the book, so nothing changes in it unseen. The editor makes each release candidate's diff readable on its own: what changed, which hearing or precedent changed it.

Supersedes. Nothing; it answers the first question kept apart in the book in release mode.

014 · The title is Generation ZX Developers (GenAI Startup Edition)

Decided. 2026-10-19

By. Dinis Cruz.

Said. "Ok agreed, let's go with "Generation ZX Developers (GenAI Startup Edition)"."

Means. The second edition's title is Generation ZX Developers (GenAI Startup Edition). It replaces the title of decision 010, Gen Z Developers (GenAI Edition), and accepts the title part of the proposal in Gen ZX Developers: the book is for Generation Z and Generation X, and its objective is a startup by the end of it. The singular is deliberate: Generation ZX is one name made of two generations, one letter away from the 2018 Generation Z Developers, and the two generations are said in full on the cover line and in the opening. "Gen ZX" is the short form; never "XZ". "GenAI" is written as one word everywhere. rc1 is frozen and keeps the old title; rc2 carries this one. Still open: whether this is the second edition of Generation Z Developers or a new book, and with it Leanpub, the ISBN, Amazon and this site's address (the publisher's brief); and the rest of the Gen ZX proposal (the audience, the objective, the new part, the remapping), which goes to the board as decided in 008.

Supersedes. The title in decision 010; decision 010 stays on the record.

Recorded in. Gen ZX Developers.

015 · The Gen ZX proposal is the frame of release candidate 2

Decided. 2026-10-19

By. Dinis Cruz.

Said. "I think we're already ready for RC2, because if you pull from the repo, you'll find the new positioning, which I think is very exciting [...] can you basically recreate the book taking that into account, and the new title and the new positioning and the content that we want to add? [...] now we have two generations and we really focus now on that whole idea of creating a company, right? The whole idea of creating a Gen AI company, a startup, and that's my target audience."

Means. The rest of the proposal in Gen ZX Developers, beyond the title decision 014 records, is adopted as the frame of release candidate 2 by Dinis's instruction to the librarian to rewrite the book under it; this change set is his own and did not wait for a hearing, so the board (decision 008) hears what comes after rc2. The book is written first for Generation Z, entering the workforce and the new entrepreneurs, and Generation X, the subject-matter experts starting companies, often their parents; the millennials in the middle may read it, and the book says briefly why it is not for them first. The reader is the founder, and the objective is that by the end of the book the reader has started a company; the book is measured by the companies created from it. The chapter map changes as the article maps it: a new part, Start the company, at the centre; Building, safely rebuilt as Build it without a server; a new first chapter; four more hands-on chapters; the measure in the last chapter. The newsroom articles the article lists are in scope and processed into ideas as the round-1 batch. The rc1 map is kept as chapters-rc1.json so the rounds page can compare the two.

Supersedes. Nothing; it completes decision 014, which took the title and left the rest to the board.

016 · A release candidate is a release: shipped on Leanpub and sold, now

Decided. 2026-10-19

By. Dinis Cruz, in pen, on page 4 of the printed release candidate 2.

Said. Beside "This is a candidate, not a version": "WRONG". Beside the paragraph about the candidate: "this is an RC which will be added to Leanpub & sold ... i.e. we are selling & shipping this book now". At the foot of the page: "this RCx → RELEASE CANDIDATE ... i.e. this should be a release → not a draft".

Means. A release candidate is released: it is published on Leanpub and sold, now, and it reads as a book, not as a working document. The book does not call itself a draft or "not a version"; it spells out "release candidate". This replaces the part of decision 009 that said a candidate is "not a version" and that "nothing is published from it outside this site": the candidate is still frozen once and read on this site from that snapshot, and its working copy is still the vault's; what changes is that the frozen candidate in this repository is what the publisher uploads. The rule that nothing is published from the vault stands. It answers the question kept apart in Version 2 on Leanpub ("upload at v2.0.0, or now?"): now.

Supersedes. In decision 009, "not a version" and "nothing is published from it outside this site"; the rest of decision 009 stands.

018 · Every release candidate has two editions: the release, and the review

Decided. 2026-10-19

By. Dinis Cruz.

Said. "I really, really like it. But it means that you now need to create two PDFs, right? There need to be two views. One, which is the release candidate, which is a book for release, literally. [...] it should not have anything that is like draft, and it's better to take stuff out than if we don't have good materials [...] I don't think it's for Dinis, make it for review, for reviewers, right? Because it could not just be me."

Means. Each release candidate is built twice from the same source. The release edition is the book for sale (decision 016): ready to put out there, with nothing that reads as a draft; where the material is not good enough yet, it is taken out, to come back in a later candidate, rather than left as a placeholder or a note. The reviewer edition is for any reviewer, not only Dinis: the same text, plus everything the release edition leaves out, the notes, the open questions, the sections flagged as having issues, the decisions waiting, and places to answer in: checkboxes for options, lines to write on, and space to draw. Every box has an id, so a photographed page is read back answer by answer into the review record, the way an agent's email draft carries its explanation and a place for the answer. Release candidates go on Leanpub as they come, for a few more rounds; when the text is stable, the print edition goes to Amazon, and the print edition is the point where the book stops changing.

Supersedes. Nothing; it extends decision 016, and the "For Dinis" notes of the candidates become the reviewer edition's boxes.

Recorded in. Two editions: the release and the review.

019 · The title is Generation ZX Founders (GenAI Edition)

Decided. 2026-10-19

By. Dinis Cruz.

Said. "I like Generation ZX founders, Gen AI edition." And, in You are a developer: "it is very hard to tell someone what they are in a word they do not relate to, so my hypothesis is that it should be called Generation ZX Founders, with "you are a developer" kept for the end, as the reveal."

Means. The book's title is Generation ZX Founders (GenAI Edition). The reader is named by the word they use for themselves, founder; "you are a developer" is the turn of the book, made in the frame chapter (Everyone who can brief an agent is a developer), not held back as a twist on the last page, because the book zooms in and keeps no punchline waiting (Zoom in, not discover). "Startup" leaves the tagline because "Founders" says it; "GenAI" stays, because it dates the book to this revolution. Generation ZX is a mindset more than a range of birth years: the people building because finally they can, seen most in Generation Z and Generation X. Short form: Gen ZX Founders; never "XZ"; "GenAI" as one word.

Supersedes. The title in decision 014; decisions 014 and 010 stay on the record.

Recorded in. Generation ZX Founders.

020 · The measure is the companies helped along the way

Decided. 2026-10-19

By. Dinis Cruz.

Said. "When we say how many companies we helped to create, I think that's too much. I think we should say how many companies we helped along the way. Some got created, some didn't got created, right? I think that's more, it also sounds less arrogant."

Means. The book measures itself by the companies it helped along the way, created or not, not by the companies it created. A founder who shipped, found out nobody missed it and stopped, and learned from it, counts. The first chapter, the last chapter and the website say it this way, and the community collects the stories, including the ones that did not become companies.

Supersedes. The measure as written in Gen ZX Developers ("how many companies have been created from it").

Recorded in. Generation ZX Founders.
