An app in a vault runs against the vault without ever being handed a key

A vault can contain an application, not only documents, and the application runs against the vault without ever holding a credential: it declares permissions of nothing, the host reads the vault and passes results in, and the app never sees a key. Capability without credential means you can run code you did not write against data you care about, with the blast radius set by a config file you can read in one screen. The same shape holds for a model: the key lives below the permission floor, the host makes the call, and the app never sees it.

Decided by. Nobody yet: a candidate for Dinis to read, comment on and decide (keep, rewrite, merge, cut, article first, later, not doing it).

Note. Belongs beside mandate-reach-gap: the config file is the written reach, enforced by the host rather than hoped for in a prompt. The chat article's qualification applies: the bridge protects the key it was trusted with; it does not yet stop a malicious app calling a provider with a credential of its own.
