Move the cloud, not the code: a twin the application cannot tell from the real service

Workloads stay on hyperscalers because moving means changing code: every call to S3, EC2 and IAM is written into applications that work today and nobody wants to touch. So the requirement is that the application must not know it has moved. The same calls land on a twin, an open source interface to a real system valued for one thing, that the client cannot tell the difference, and the twin decides where the bytes go: real S3, an sgit vault, a European operator's data centre, a laptop. Switching a mock costs a code path; switching a twin costs an endpoint, so migration becomes a configuration decision rather than a project, and projects get cancelled. The S3 twin exists as open source; EC2 and IAM do not yet.

Decided by. Nobody yet: a candidate for Dinis to read, comment on and decide (keep, rewrite, merge, cut, article first, later, not doing it).

Note. Dated 12 October 2026, from a digital sovereignty event; the chief executive is not named and did not review it. AWS's European Sovereign Cloud went live on 15 January 2026, a separate cloud with its first region in Brandenburg, operated by EU residents; the article's reading: 'Sovereignty that depends on one company's API is sovereignty by permission.' None of it works if the twin layer is closed: swap one vendor's API for another vendor's proprietary wrapper and the lock-in has moved, not gone.
