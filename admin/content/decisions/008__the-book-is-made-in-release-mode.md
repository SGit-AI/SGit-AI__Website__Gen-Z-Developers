# The book is made in release mode, through a review board

**Decided.** 2026-10-19

**By.** Dinis Cruz.

**Said.** "Let's do the book in release mode, right? So can we have a first release candidate of the book?" And: "let's create a sort of adversarial sort of review board where once we got that first release candidate, then every word, every change, every idea that we're going to add to the book needs to go through that sort of process."

**Means.** The librarian's first list (the ideas register and the proposed chapter map) becomes the first release candidate of the book, rc1, in the vault. Then rounds: each takes a pile (the concepts of this site's articles not in the text, then what the 2018 book had, then the newsroom's articles, and any new article as it comes), and each ends in the next release candidate. After rc1, nothing enters the book without going through the review board (`team/board/role.md`): an advocate, a cutter, the readers, a checker and the editor make the case for and against, and Dinis decides. Every verdict is recorded with its reason; a general reason becomes a precedent, applied before a hearing is called, on a list Dinis can overturn. Verdicts: add, rewrite, merge, sign off, next version, another book, not in this version (with the reason). Release candidates are working versions and stay in the vault; only a signed-off one, agreed official by the publisher, comes into this repository, numbered as decision 006 says.

**Supersedes.** Nothing; it is the loop of [read, comment, decide](/articles/read-comment-decide.md) applied to the whole book, round by round.

**Recorded in.** [The book in release mode](/articles/the-book-in-release-mode.md).
