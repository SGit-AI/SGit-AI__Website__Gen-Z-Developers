# Every release candidate has two editions: the release, and the review

**Decided.** 2026-10-19

**By.** Dinis Cruz.

**Said.** "I really, really like it. But it means that you now need to create two PDFs, right? There need to be two views. One, which is the release candidate, which is a book for release, literally. [...] it should not have anything that is like draft, and it's better to take stuff out than if we don't have good materials [...] I don't think it's for Dinis, make it for review, for reviewers, right? Because it could not just be me."

**Means.** Each release candidate is built twice from the same source. **The release edition** is the book for sale (decision 016): ready to put out there, with nothing that reads as a draft; where the material is not good enough yet, it is taken out, to come back in a later candidate, rather than left as a placeholder or a note. **The reviewer edition** is for any reviewer, not only Dinis: the same text, plus everything the release edition leaves out, the notes, the open questions, the sections flagged as having issues, the decisions waiting, and places to answer in: checkboxes for options, lines to write on, and space to draw. Every box has an id, so a photographed page is read back answer by answer into the review record, the way an agent's email draft carries its explanation and a place for the answer. Release candidates go on Leanpub as they come, for a few more rounds; when the text is stable, the print edition goes to Amazon, and the print edition is the point where the book stops changing.

**Supersedes.** Nothing; it extends [decision 016](/decisions/index.html#a-release-candidate-is-a-release-shipped-and-sold), and the "For Dinis" notes of the candidates become the reviewer edition's boxes.

**Recorded in.** [Two editions: the release and the review](/articles/two-editions-the-release-and-the-review.md).
